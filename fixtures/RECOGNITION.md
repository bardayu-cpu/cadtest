# 户型识别测试基准

Issue #12 只标注 `floorplan-a.jpg`；`floorplan-b.jpg` 尚未标注。Issue #13 的基准脚本自动枚举 `fixtures/floorplan-*.jpg/jpeg/png`，两张图均调用实际识别管线，仅有对应 `expected.json` 的图进入评分。

## 数据与人工校对

`floorplan-a.expected.json` 复用模型的 `Wall`、`Opening`、`Room`，所有元素均为 `source: "manual"`。坐标以原图左上角为原点，x 向右、y 向下，单位毫米；图像坐标 = 模型坐标 / `mmPerPixel`。原图尺寸为 1264 × 921 像素。

采用 **15.52 mm/px**。尺寸线端点按原图端部刻线人工读数，保存在 `calibration` 中，可独立重算：

| 尺寸线   | 起点像素   | 终点像素   | 标注长度 mm | 推算 mm/px |
| -------- | ---------- | ---------- | ----------- | ---------- |
| 上侧总长 | (123,45)   | (1091,45)  | 15040       | 15.53719   |
| 上侧客厅 | (137,64)   | (549,64)   | 6390        | 15.50971   |
| 上侧次卧 | (562,64)   | (754,64)   | 2980        | 15.52083   |
| 上侧主卧 | (763,64)   | (974,64)   | 3270        | 15.49763   |
| 右侧总高 | (1167,126) | (1167,797) | 10430       | 15.54396   |

五条尺寸线最大与最小估算相差 **0.299%**，每条与采用值相差不超过 **0.155%**。上下两侧总长重复标注只计为一条独立证据。不要混用左侧总高 10480 与右侧总高 10430，它们的上端墙轮廓有高差。

墙体按连续轴线段计数，遇方向改变或厚度改变拆段，门窗洞口仍保留所在墙的连续轴线；T 字交点不额外拆分。描线以结构墙为准，十字柜体、电视、床、橱柜、洗衣设备与尺寸线不算墙；左上转角的局部阶梯轮廓不增加墙轴线。模型只表达矩形墙段，不单独表达局部柱墩的截面轮廓。外墙主要为 14 px（217.28 mm），薄隔墙为 8 px（124.16 mm）。

| 范围                             | 墙编号  | 段数   |
| -------------------------------- | ------- | ------ |
| 外圈及上方凹口                   | w01–w07 | 7      |
| 上方卧室与主卫隔墙、转折         | w08–w14 | 7      |
| 左下外圈、厨房、洗衣区、下侧横墙 | w15–w22 | 8      |
| 右下外圈和下方房间隔墙           | w23–w29 | 7      |
| 合计                             |         | **29** |

门窗共 **15** 处：7 樘平开门、6 樘普通窗、1 处厨房推拉门、1 处右侧卧室落地窗。`Opening.offset` 是洞口中心沿墙从 `start` 起算的毫米距离，`width` 是洞口完整宽度。厨房上方两片带中间竖缝的长开口按推拉门标注；右侧卧室整段多线外窗按落地窗标注。高度在这张平面图上不可测，采用规格默认：门 0–2100 mm，普通窗 900–2400 mm，落地窗 0–2400 mm。

空间共 **9** 个，边界沿墙中心线，客餐厅及其敞开通道合为一个凹多边形：

原图没有房间名称，类型由床、洁具、灶台和洗衣机符号人工判断；下中房间用途不明确，按规格保留 `other`。厨房与生活阳台之间的门位于**竖墙**；右侧卧室入口也位于**竖墙**。

## 重现叠加图与基准

```sh
nvm use
npm ci
npm run overlay -- fixtures/floorplan-a.jpg fixtures/floorplan-a.expected.json tmp/floorplan-a.overlay.png
npm run bench:recognize
npm run overlay -- fixtures/floorplan-a.jpg tmp/floorplan-a.recognized.json tmp/floorplan-a.recognized.png
npm run overlay -- fixtures/floorplan-b.jpg tmp/floorplan-b.recognized.json tmp/floorplan-b.recognized.png
npm test
```

叠加图青色为墙中心线及透明墙厚，橙色为门（包括推拉门与门洞），品红为窗，绿色为房间。脚本也可接受任意符合 `RecognitionData` 的识别结果 JSON。只能输出到 `tmp/` 内，自动生成本地 `tmp/.gitignore` 防止误提交图片；PNG 作为 PR 评论附件上传。

评分使用 `recognizeFloorPlan` 的真实比例尺和墙体结果；识别代码不读取标准答案。`tmp/bench-recognize.json` 与 `.md` 保存机器、评分和耗时，`tmp/*.recognized.json` 保存诊断与自动墙体。门窗、房间属于后续 Issue，当前只报告比例尺与墙体；B 图无标准答案，评分明确显示 N/A。实现与当前差距见 `src/recognize/README.md`。

评分定义：比例尺为相对于标准答案的绝对相对误差；未检测或无效值返回 `null`。墙的方向无正反之分，角差严格小于 3°，整段中心线对称 Hausdorff 距离严格小于 100 mm，因此短碎片或同一无限直线上的远端段不能命中。门窗按类型比较世界坐标中的中心，距离严格小于 200 mm，墙编号无需相同。房间支持凹多边形、反向绕序，以 IoU ≥ 0.8 为几何匹配，再统计其中类型一致的数量。三类元素均使用最大基数二分图一对一匹配，禁止重复计分。

准确率 = 匹配数 / 识别数，召回率 = 匹配数 / 标准答案数。标准答案与识别都为空时两者为 1；仅识别为空且标准非空时两者为 0；标准为空但有误报时准确率为 0、召回率为 1。表格同时列出数量，避免把无该类型的 100% 误解成识别成功。
